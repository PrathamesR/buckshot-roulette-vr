# AGENTS.md - Buckshot Roulette VR mod

Start here. This file says **how to work on the project**. The details live in other files in the same folder:

- `README.md` - plain-language overview for anyone (non-technical readers too): what it does, how to run it, controls. No internals.
- `ARCHITECTURE.md` - technical reference: game/engine facts, how the mod is built, log lines, how to test, gotchas.
- `CHANGELOG.md` - history by iteration, what the user has confirmed, what is unverified, backlog.

**Maintenance rule (user's explicit request): in the same turn as every change, update these files** - CHANGELOG.md and
"Current state" below always; ARCHITECTURE.md when the architecture, constants or game facts change; README.md when features,
controls, setup or status change (keep it jargon-free).

## What this is
A personal VR mod for Buckshot Roulette (Steam, v2.2.0.6, custom Godot 4.1.1 + OpenXR build) for a Quest 3 via Virtual Desktop
(should work with any OpenXR headset). The mod is one GDScript autoload: the entry file `vr_boot.gd` plus a chain of modules in `src/` (one class, split over files). The agent writes the code; **the user tests
in the headset** (the agent cannot see VR). The user is often away from the PC: send short test checklists, read `logs/godot.log` after tests.

- The notes are public (GitHub): no verbatim user messages, no real Windows account name (`<WINDOWS-USER>`; the real device path comes from `get_device_info` / `device_list_dir`).
- Never search the whole PC. Only use the folders the user granted (see "Folders" below). Ask when
  something else is needed.
- Limit screenshot checks while working; too many waste time.
- Replies are read on a phone: lead with the answer, concise, short lists, no recap of steps.
- The extracted game project is private, for personal modding only, **never redistributed**. The final mod must
  contain only our own code/assets.

- Send a one-line status before long work if the user has not heard from you; use the task list for progress.
- Keep these notes up to date (AGENTS.md, README.md, ARCHITECTURE.md, CHANGELOG.md) so no one re-learns the project.

## Folders, files, how to deploy

Windows paths (user's PC), reached through the device bridge (`mcp__remote-devices__*`; mounts under
`$HOME/mnt/<folder-name>` inside `device_bash`):

| What | Windows path | Bridge mount name |
|---|---|---|
| Game | `F:\SteamLibrary\steamapps\common\Buckshot Roulette\Buckshot Roulette_windows` | `Buckshot Roulette_windows` |
| Mod + user data + logs | `C:\Users\<WINDOWS-USER>\AppData\Roaming\Godot\app_userdata\Buckshot Roulette\` | `app_userdata--Buckshot Roulette` |
| Extracted game project (READ ONLY analysis) | `F:\Project\VR Modding\Buckshot Roulette\` | `VR Modding--Buckshot Roulette` |

If a folder is not mounted in a new session, ask the user to grant it (`device_request_folder_access`); do not browse elsewhere.

Inside the user-data folder:
- `vr_mod/vr_boot.gd` + `vr_mod/src/*.gd` - **the mod** (source of truth is the device folder; the agent keeps a mirror of the whole tree in its outputs folder `vr_mod/`). `src/README.md` lists the modules and the chain rules.
- `vr_mod/tools/check_modules.py` - checks the chain rules (stubs, declaration order). `vr_mod/tests/` - offline suites: `tests/run.sh <godot-binary> [suite]` (see `tests/README.md`).
- `vr_mod/AGENTS.md`, `README.md`, `ARCHITECTURE.md`, `CHANGELOG.md` - these notes.
- `vr_mod/archive/backups/vr_boot.iterN.bak` - backups of every earlier iteration (iter2 ... latest-1). Roll back by copying one over `vr_boot.gd`.
- `vr_mod/vr_settings.cfg` - saved settings: `scale_big, seat_big, scale_small, seat_small, panel_visible, monitor_view, retro_look, glide, stick_walk, vignette, hint_dim, hand_lit, size_gesture2, help_sign, gun_cal_x, gun_cal_y, gun_cal_z` (an old `spectator_3d` key is ignored). (The user's tuned big scale is about 6.6 game units per metre = the code default `DEFAULT_SCALE_BIG`.)
- `vr_mod/hands/` - the game's hand meshes extracted by the mod at run time (game-derived: git-ignored). `walkmap.png`, `window_probe_*.png` are written by the mod at run time (git-ignored); older copies are in `vr_mod/archive/probes/`.
- `vr_mod/archive/` - everything that is not needed at run time: `backups/` (old iterations) and `probes/` (`gun_probe.json`, `probe_hands.json`, `layout_dump.json`, `hands_preview.png`, `H_tmp.npy`, `Hphone_tmp.npy`, `hands_tmp.npz`, old probe pictures). `vr_mod/.gitignore` keeps the personal settings, the game-derived files and `archive/probes/` out of a repo.
  `gun_probe.json` and `probe_hands.json` (iterations 20-21: decoded gun and hand meshes used for the offline grip fit) are game-derived analysis files: private, never part of the mod, never redistributed; they are not needed at run time.
- `logs/godot.log` (latest run) and `logs/godot<timestamp>.log` (older runs). **Read the log after each user test.**

Injection: `override.cfg` in the game folder (the only change there). Two forms, both load the same files:
```
[autoload]
VRBoot="*user://vr_mod/vr_boot.gd"      <- the developer setup (files in %APPDATA%...\vr_mod, proven in the game up to iteration 38)
VRBoot="*res://vr_mod/vr_boot.gd"       <- the release zip (files in <game folder>\vr_mod; works in a simulated packed game, NOT yet tried in the real game)
```
Launch (from the game folder, PowerShell): `& ".\Buckshot Roulette.exe" --xr-mode on`

Deploy procedure for every iteration:
1. Edit the module file(s) (copy the tree to a work folder first; use exact-match replaces with an assert on the count). Run `python3 tools/check_modules.py` and `tests/run.sh <godot> <suites>` (ARCHITECTURE.md "How to test without a headset"). Add a test for what you changed.
2. On the device: back up the code: `cd vr_mod && tar czf archive/backups/code.iter<N-1>.tar.gz vr_boot.gd src` (via `device_bash`).
3. `device_commit_files` with the changed files only (staged `/mnt/user-data/outputs/vr_mod/<path>` -> `C:\Users\<WINDOWS-USER>\AppData\Roaming\Godot\app_userdata\Buckshot Roulette\vr_mod\<path>`, at most 50 files per call).
4. Verify with the fingerprint `cd vr_mod && md5sum vr_boot.gd src/*.gd | md5sum` on both sides (and the notes); the numbers must match. Put the new fingerprint into "Installed" above.
5. Update the notes (Current state above, CHANGELOG.md, and README.md / ARCHITECTURE.md if needed) and commit them the same way.
6. Tell the user briefly what changed and give a 2-3 item test list that flags what is unverified.
