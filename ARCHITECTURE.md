# Architecture and technical reference

For developers and agents. The plain-language overview is in README.md; how to work on the project (rules, folders, deploy) is in
AGENTS.md; history and open items are in CHANGELOG.md. **Keep this file in step with the code**: update it when the architecture,
constants or game facts change.

## Engine and game facts

### Godot 4.1.1 build limits (cost us several iterations)
- **No `fog_disabled` render mode and no `BaseMaterial3D.disable_fog`** (added in 4.2). Using them makes the shader fail to compile
  -> dead menus, white hands. Never use them. Fog exists only in the menu scene (density 0.6255, colour about 0.035 near-black);
  the main scene has fog off. Straight-alpha `blend_mix` quads are immune to fog tinting where alpha = 0 (the panel uses that).
- `Vector3.min/max` do not exist; typed `:=` needs an explicit type when the value is a Variant.
- Shader compile errors only show in the log at run time; the cloud sandbox has no Vulkan, so shaders are compile-tested with the
  compat renderer (see "How to test without a headset").
- AnimationPlayer: `seek(t, true)` applies at once; method tracks do not fire on seek; audio tracks restart from the offset
  (our fallback plays the kick sound by hand if it does not).

### Rendering/grading
- The XR rig lives in its own `SubViewport` that **shares the root World3D**, so the game's Environment, lights, tonemap and
  adjustments apply to our meshes. Game grade: ACES, brightness 1.49, contrast 0.8, saturation 0.26. Ambient light energy is 0:
  the main scene is lit only by about 29 mostly warm-orange OmniLights (energy 8-33, ranges 15-80 units).
- World scale: about 6.6 game units per metre in the building (main scene, camera y < 30), 0.9 in the menu/car intro.
- Render priorities: blackout sphere 100, text panel 101, pause quad 102.
- **The game's own screen effects (what makes the PC look).** Every scene (menu, main, death, heaven) has `Camera/post processing/` with Control + BackBufferCopy +
  ColorRect nodes, each a canvas shader on the *final* picture (after tonemap and brightness/contrast/saturation, 8-bit sRGB values): `posterization test`
  (`res://main player/posterization test.gdshader`: per channel `floor(c * N) / N`, N = `RED/GREEN/BLUE_COMPONENT` = **7.0**; the only one visible by default),
  `opengl post processing` (vignette.gdshader colour grade; hidden unless the game runs on the OpenGL pipeline), `color precision`, `dithering` (ordered 4x4 dither +
  floor(c*10)/10) and `test` (all hidden). The window itself is 960 x 540 (`window/stretch/mode="viewport"`) and is scaled up, which is the chunky pixel look; the
  mod does not copy that. The mod hides all BackBufferCopy nodes (they would paint over the 2D window that the panel mirrors) and reads N first (`_read_retro_levels`).
- **Retro colours (iteration 14).** A canvas shader cannot run in the headset, but the engine's last 3D step can do the same rounding: `tonemap.glsl` (4.1.1) runs
  exposure -> tonemap -> `linear_to_srgb` -> glow -> **BCS** -> **colour correction (LUT)** -> debanding. `Environment.adjustment_color_correction` set to a `Texture2D`
  selects the 1-D table (`use_1d_color_correction`), looked up per channel as `texture(lut, vec2(c, 0))` with linear filtering and clamping, after BCS (which is not clamped).
  `_build_retro_lut(levels)`: 1024 x 1 RGBA8, texel i = floor(((i + 0.5) / 1024) * N) / N, last texel 1.0 (a pure white stays white, as in the game); step edges are one
  texel (0.1 %) wide. `_update_retro` (4x/s) puts it on the current `world_3d.environment` (each scene has its own Environment), sets `adjustment_enabled = true`, remembers
  the previous table/flag and puts them back when the setting is switched off or the scene changes. Applies to everything in the picture, also our hands, panel, laser,
  brackets and the monitor picture (same world environment). Side effect: our UI colours are rounded too (the game's lime becomes about (0.71, 0.86, 0.29)); the pause
  and sign shader has a `retro` uniform: tone 1.0 (instead of 0.9 / 0.85) and whites (min channel > 0.97) are pushed to HDR 3.0 so they clip to exactly 1.0 and are
  not rounded down to light grey. Setting `retro_look`, pause button "Retro colours". Scenes without a visible posterization node (`retro_levels` zero) get no table.

## How the mod works (architecture; code in `vr_boot.gd` + `src/`)

### Code layout (iteration 39)
One class, split over a chain of files: `vr_boot.gd` (entry: `_ready`, `_process`, `_input`) extends `src/36_cuffs.gd`, which extends `35_paper.gd`, ... down to `src/00_core.gd` (`extends Node`; shared constants and variables). `src/README.md` has the table of modules and the rules (call down the chain directly, call up through a stub in `01_forward.gd`, declare a variable in the earliest file that uses it); `python3 tools/check_modules.py` checks them. Function names are unchanged, so the notes below still apply: where they say "in `vr_boot.gd`", find the function with `grep -n "func _name" src/*.gd`. The section map below follows the OLD single-file order; the module tables replace it for navigation. The inner class `Hand` is `src/hand.gd` (`const Hand = preload("hand.gd")` in core). Godot loads a script's parent from a relative `extends "x.gd"` path, so the chain works from `res://` and `user://`.


One `Node` autoload (`process_mode = ALWAYS`). `_ready` builds: `XROrigin3D` + `XRCamera3D` in an XR `SubViewport`, two hands
(`Hand` class: grip/pointer trackers, pose, laser), laser dot, text panel, pause UI, fx_root (beacon, vignette, bracket mesh,
blackout sphere, kick leg). `_process` order: refs -> highlight suppression -> door logic -> anchor -> blackout -> scene scan ->
tuning keys -> pending recenter -> hand poses/grade -> bounds -> poke -> TV -> pill -> walk -> **size gesture -> bathroom sign** -> pointer -> buttons -> brackets ->
panel -> visuals -> diagnostics -> `_rig_guard`.

Section map (function groups, in file order): frame loop; game hookup (anchor, regime, `_place_origin`); hands; the game's own hands
(procedural finger-curl poses: open, point, trigger, thumbsup, flip, fist; two hand shaders); pointer (physics ray vs. world, panel
ray, aim assist, `_room_mask/_behind_wall`); buttons (trigger/grip/stick/A/B mapping); panel (mirrors the 2D window on a quad with
PANEL_SHADER); laser visuals; world size/height by hand and the bathroom sign (iterations 11-12); pause menu (own SubViewport on a quad, 18 buttons (14 before iteration 24) in 2 columns, 1000x724 px = 1.1 x 0.796 m); fades (blackout sphere); walking (stick walk,
snap-turn, leash, `_arrive_at_table`, `_note_click_target`); bathroom by hand (door/TV poke, pill bottle pick-up/eat, pill
"CONSUME PILLS?" prompt); the back-room door (kick in place); highlights and clutter hiding; walking limits (bounds); floor-plan dump;
click targets/brackets/aim assist; retro colours and the PC monitor (iteration 14); scene scans and window probe; misc (diagnostics, settings).

### PC monitor (iteration 14)
- Why it was blank: `root.disable_3d = true` (the window must not render the 3D world a second time at full cost; the XR rig has its own viewport) and
  `root.transparent_bg = true`, so the window showed only the game's 2D over black. (Iterations 1-13 had an F3 switch that turned the window's 3D back on; that
  also put the 3D picture into the window texture the panel reads - removed.)
- Design: the panel reads the window texture, so the monitor picture must not be drawn into it. Instead (a) `ui_vp` is a `SubViewport` (960 x 540, transparent) with
  `world_2d = root.world_2d`: it draws the *same* default canvas as the window (the game has no CanvasLayer in its scenes except the multiplayer lobby), so it is a
  picture of the game's 2D alone - the panel (`_ui_tex()`) and `_probe_root` read it; (b) `spec_vp` (same size, 3D on, shares the root World3D like the XR viewport) with
  `spec_cam`, shown by a `TextureRect` in a `CanvasLayer` (layer -100, under the game's 2D) in the window. Checked in 4.1.1 (GL test `mon_test.gd`): the copy keeps
  pixels, empty alpha 0 and half-transparent alpha; the camera sees the game world and nodes under the XR viewport; a layer-20 node is hidden.
- Camera (`_update_monitor`): follows `xr_cam` position (smoothing 18/s, snaps if it jumps > 3 m) with yaw/pitch only (smoothing 8/s, no roll -> level horizon),
  FOV `MONITOR_FOV` 74 (vertical), near `MONITOR_NEAR_M` x max(world_scale, 1). The vignette and the fade sphere are on `LAYER_HEAD_ONLY` (layer 20, excluded by
  `spec_cam.cull_mask`): the window's own 2D already draws the game's fades over the picture. The window is presented opaque (alpha ignored).
- Cost: a second 3D render at 960 x 540 (about +4 % of the pixels of the headset picture, plus its own shadows). `monitor_view` off -> both viewports `UPDATE_DISABLED`,
  layer hidden, panel back on the window texture. F3 and the pause button toggle it (`_monitor_apply`).
- Safety net `_monitor_selfcheck`: when the game's black fade rectangle is ~opaque (`blocker_alpha_raw` > 0.97 for 4 frames) the 2D copy's corner alpha must be ~1; if it
  is 0 the shared canvas did not work on this machine and the monitor view is switched off for the session (logged), so the panel can never stay blank.

### Position model (the part that bites)
- `anchor_pos/anchor_yaw` = where the game wants the player's eyes. `mode`: `"table"` (fixed at HOME, ignores the game camera) or
  `"follow"` (anchor glides to the game camera's position; rotation is not copied).
- Head target = `anchor_pos + walk_off + Basis(UP, anchor_yaw) * seat`. `_place_origin()` moves the XR origin so the real head lands
  there. `walk_off` = how far stick walking has taken you from the anchor. It is only maintained while NOT in free-walk
  (`walk_to_table` or `hold_for_dealer` or `kick_on`); in free-walk call **`_sync_walk_off()`** before any `_place_origin`, otherwise a
  re-seat drops you on the game camera. (This was the cause of the "teleported back" bug.)
- `_request_recenter()` schedules a re-seat after `RECENTER_SETTLE`. It is triggered by hops/cuts (camera moved > `CUT_DIST` 8 in one
  frame, ignored while `kick_on`), re-facing after a walk (only if `walk_off` < 1 m), regime change (small<->big), table arrival.
- Anchor carry (`origin += d`) happens only in follow mode when not `needs_recenter`, not `hold_for_dealer`, not `kick_on`.
- `walk_to_table`: the game is ready at the table, but you are far away -> you walk there (green beacon), auto-seated when within
  `ARRIVE_M` or idle `WALK_TABLE_IDLE_S`.
- `_rig_guard()`: during `kick_on` (and mode != table) any head jump > 2 + 25*dt units in a frame is undone and logged
  ("guard: undid a sudden move ..."). Outside the kick it only logs "rig jumped ...".

### Back-room door (iteration 9/10 design)
`_update_door` every frame: sets `interactionInvalid` on `intbranch_backroomdoor` unless you are within `DOOR_REACH_M` (2.6 m) of
`DOOR_CENTER` (only when stick walking is on, big regime, follow mode). A click when too far is ignored (red bracket + haptic).
When the game starts "camera enter backroom": `_kick_start` pins the rig (`hold_for_dealer`, `_sync_walk_off`), makes a copy of the
game's leg mesh, holds back the lobby (`_club_hold` empties `objArray_club` so `BeginGame` hides nothing), seeks the animation to
`KICK_FROM_S` (2.9 s) so the camera walk is skipped, calls `PanFilter` by hand, and re-bases `prev_cam_pos` so it is not a "cut".
`_kick_update` draws the leg copy between 3.3 and 4.1 s, moved so its path starts at **your** feet and kicks along the line from you to
the door (`kick_k` scales the stride). `_kick_end` frees it. The lobby is hidden by `_club_release` once your head passes `CLUB_HIDE_X`
(-33). After the animation the camera reaches home -> mode "table" -> you walk to the seat.
The **bathroom** door (iteration 13) gets the same treatment, with its own numbers (`BATH_*`): pressing the door by fingertip (`_poke_fire`)
pins you immediately (`hold_for_dealer` + `bath_pending` + `_sync_walk_off`; no dealer beacon for it); when "camera exit bathroom" starts,
`_kick_start(intro, player, true)` seeks to `BATH_FROM_S` (1.15 s), draws our copy of the leg (1.38-1.82 s; path rebased from `BATH_KICK_CAM`, aimed at
`BATH_DOOR_CENTER` (-138.47, -1.19), stride `kick_k = (dist + 0.5) / 11.33`), and the animation itself swings `bathroom door` open at 1.46 s and fires
`KickDoorLobby` (filter pan, restroom ambience off) at 1.48 s; the kick sound is started by hand if needed (`kick door enter lobby.ogg`). While it
plays the game camera flies through the doorway to the lobby start (-117.48, 7.32, 0.02, yaw -131.8 deg) but you are not carried. `_kick_end`
(bathroom) sets `anchor_pos` to the game camera, re-syncs `walk_off` and releases `hold_for_dealer`: you are in the bathroom, 30-55 units from the
anchor, and walk there yourself (`gap_bath_open` was set at the press so the doorway is walkable). The old carried version (leg un-hidden by
`_bathroom_leg` between 1.3 and 2.4 s) remains only as the fallback when stick walking is off. The per-door numbers live in the vars
`kick_door/kick_cam/kick_len/kick_past/kick_on_s/kick_off_s`, set by `_kick_start`.

### Hints/aim
- Laser = physics ray; if nothing clickable is under it, **aim assist** (`_assist_hit`) pulls onto small/far targets. Both ignore
  things in other rooms. `POKE_ALIASES` (crt, crt button, bathroom door, backroom door) are pressed only by fingertip; `HIDE_HINT_ALIASES` have no
  laser hint (pill bottle is picked up by hand, pill choice by the prompt).
- Brackets: bright green = pointed at (red if invalid), tight small ones near a fingertip; faint ambient `[ ]` on everything
  clickable are OFF by default (`hint_dim`, pause-menu switch). The game's own 3D brackets (`bracket selection 3d*`) and legs are
  hidden by setting `layers = 0`.

### World size and height by hand (iterations 11-13)
- Trigger: both `grip_sq` for `SIZE_ARM_S` (0.35 s), not while paused / pill in hand (`pill_state == 1`) / `kick_on` / `needs_recenter`,
  setting `size_gesture`. (Iteration 11 also required `tv_state == 0` and hands > 10 cm apart: with the TV left on the gesture never started - removed in 12.
  The blocking reason is logged once per hold: `both grips held but not started (<reason>)`.) While active both hands have `holding = true`
  (fist pose, no poking) and `_pill_idle` ignores them.
- Inputs are the **raw** controller poses (`hh.grip.get_pose().transform.origin`, metres, no world scale; fallback `grip.position / world_scale`,
  logged once) so changing the scale does not feed back into the measurement. At the start the raw hand distance is compared with the node distance /
  world_scale; if the raw one is < 3 cm while the nodes say > 5 cm, `size_use_nodes` switches to the node positions (logged).
- **Reference vs default (iteration 13).** The readout ("SIZE n %", "HEIGHT +n CM") counts from the old defaults: `REF_SCALE_BIG` 6.6 / `REF_SEAT_Y_BIG` 0.62
  (small: 0.9 / 0.64) = 100 % / +0 cm. The real defaults are `DEFAULT_SCALE_BIG` 13.2 (= 6.6 / 0.5, shown as 50 %) and `DEFAULT_SEAT_BIG` y 2.6
  (= 0.62 + 0.15 m * 13.2, shown as +15 cm); small 1.8 and y 0.91. Limits: size `SIZE_MIN` 0.25 .. `SIZE_MAX` 2.0 of the reference; height
  `ref_y - 0.3 * def_s` .. `ref_y + 0.5 * def_s` (so -30 / +50 cm at the default size; fixed in game units, not per scale).
- `_size_targets(ref_s, ref_y, def_s, def_y, p0, y0, d0, d, hy0, hy, cur_s)` (pure maths): p = clamp(p0 * max(0.2, 1 + (d - d0) / SIZE_REF_M), 0.25, 2.0),
  `SIZE_REF_M` 0.4 (linear in the hand distance, works from any start distance), snaps to the default p (0.5) within 6 %; scale = ref_s / p;
  seat.y = clamp(y0 + (hy0 - hy) * cur_s, ...), snaps to `def_y` within 2 cm. Smoothed with `1 - exp(-SIZE_SMOOTH*dt)`.
  `_def_scale()/_def_seat()` and `_ref_scale()/_ref_seat_y()` give the numbers of the current regime.
- Only `world_scale` and `seat.y` change (seat x/z stay), then `_apply_scale()` + `_place_origin(true)`: the head is **pinned** to anchor + walk_off +
  seat like the F5/F6 keys, so scaling cannot slide or lift you (cost: leaning does not move the view while the gesture runs). `_size_hold_here()` at
  the start syncs `walk_off` to where you stand (not at the table).
- On release `_size_end` applies the same ratio / metre change to the other regime (car intro / menu <-> building, clamped) and saves. Pause
  "Reset size and height" -> `_size_reset` (defaults; re-opens the pause menu so its pointer maths match the new scale). A `Label3D` readout
  ("SIZE 50% / HEIGHT +15 CM", in the game font) follows the hands and stays 1.8 s after release.
- Haptics: tick per 5 % size / 5 cm height, firm tick on reaching exactly the default.

  space at `HELP_POS` (-141.5, 7.9, 12.0), `HELP_SIZE` 11 x 8 units. `_help_transform()` gives the basis: local +Z = (-0.958814, 0, -0.284034) (into the
  room), +X = (-0.284034, 0, 0.958814) (to the viewer's right). It lies 0.12 units in front of the dark plate right of the bathroom door: `Cube_117`
  in `scenes/main.tscn` (materials "heavy rust"/"stall door"; restroom_CLUB transform rotated 180 deg about Y at (-157.862, -8.2305, -0.4033); the
  plate's room-facing plane runs through world (x, z) = (-139.51, 5.71) and (-143.26, 18.37), 12.66 units along the wall; the sign is centred on it).
  Iteration 11 had it on the mirror wall (-152.5, 9.4, -19.76): the user did not like that and asked for this plate. Its position is derived, never seen
  in the headset yet.
- Content: title CONTROLS (green-yellow) and 5 rows TOUCH / PILLS / MOVE / SIZE / HEIGHT (heading green-yellow, one short line white each) and a
  TAKE DOWN button (`HELP_CLOSE` Rect2(300, 694, 500, 82) px). Dismissal: a fingertip within `2 * POKE_PAD_M` of it (since iteration 19 the laser route - `help_hover` in `_update_pointer`, laser forced
  visible/blue, game click suppressed - is off while `_physical_only()`); hover = green-yellow fill, black text.
- Shown only when `help_sign` and not `help_hidden_run` and in the restroom (`_room_mask == 1`, big regime, main scene, not paused, not during the door kick). Taking it down
  (iteration 15) sets `help_hidden_run = true` (this run only, NOT saved; it is back at the next start); the pause button "Bathroom sign" shows OFF while hidden and brings it
  back (sets `help_sign = true`), otherwise toggles the saved `help_sign`. A fingertip touch needs: 1.5 s since the sign appeared (`HELP_GRACE_S`), and the tip coming from the
  head's side of the sign into the `2 * POKE_PAD_M` zone (previous frame outside it) - a hand already there or sliding in sideways does not count. Reason: in iteration 14
  a trigger on the button (log: `taken down (trigger, right hand)`) saved `help_sign=false`, and the user did not know why the sign was gone.
- **Game look for our own screens** (pause menu, sign, size readout): the game's menu font `res://fonts/fake receipt.otf` (`_game_font()`, loaded at
  run time from the game's own data, cached in `ui_font`; null -> default font with a log line) and only the game's colours: `UI_BLACK`, `UI_WHITE`,
  `UI_LIME` Color(0.776471, 0.87451, 0.380392) (the game's option-value colour). Buttons: black with a white border, lime on hover (black text), white
  when pressed (`_box(bg, border, width)`); 26 px labels with 8 px margins so 21-22 character labels fit the 428 px column. The font is dot-matrix
  capitals only. Render tests need the staged font: `FontFile.load_dynamic_font("/tmp/fake_receipt.otf")` assigned to `vb.ui_font`.

### Items locked until you sit down (iteration 13)
`_items_locked()` = main scene, big regime and (`mode != "table"` or `walk_to_table` or `hold_for_dealer`). Then `_alias_locked(alias)` is true for every
alias not in `PRESEAT_ALIASES` (crt, crt button, bathroom door, pill bottle, pill choice yes/no, backroom door). Applied in `_update_pointer` (the ray
result is not fed to the game: `feed = {}`; the laser itself still stops at the object), `_assist_hit`, hover and faint brackets (`_update_brackets`) and
fingertip targets (`_update_poke`). Unlocks when `_arrive_at_table` runs (or "Recenter here").

### Highlights (brackets)
`_add_bracket_for_box` sizes everything with `BRACKET_UNIT` (6.6 game units per metre) instead of `world_scale`: when you are small the things are
small, so their frames must be too. Minimum half-size `BRACKET_MIN_M` 0.06 (pointed at) / `BRACKET_MIN_DIM_M` 0.05 (faint), padding `BRACKET_PAD_M`
0.025 + 5 % of the size, line width `clamp(dist * 0.004, 0.006, 0.04) * unit`. Frames are drawn around the **collision shapes** of the click target, so
a target whose collider is larger than the visible object still gets a large frame (only a visual test in the headset tells).

### Game phase: name machine and shotgun (iteration 13 start)
Game facts (from the extracted project): the waiver (`release form on table`, alias) -> `Signature.PickUpWaiver()` shows the machine; **28 keys**, each an
`InteractionBranch` with alias `signature machine button` and `signatureButton_letterAlias` / `signatureButton_specialAlias` (`enter`, `backspace`),
`SignButton.Press()` dips the key; `InteractionManager.InteractWith` calls `sign.GetInput(...)`. The name has 6 letters max; `enter` runs the
punch-in animation and starts the round. The machine and form are only interactive after `PickUpWaiver` (2.77 s later `intbranches` allowed).
Hand control done so far: `FINGER_ALIASES` (the keys and the waiver) are touched with the index fingertip (`_update_poke` picks the closest target per

### Distribution (2026-11-10): zip + launcher
- **How the mod is injected.** Godot reads `override.cfg` from the folder of the game's pack (= the game folder; the exe's working folder works too) and adds the `[autoload]` entry. An autoload path `*res://vr_mod/vr_boot.gd` finds a **loose file next to the pack** when the pack does not contain it (found by experiment: Linux Godot 4.1.1 with `--main-pack` of a tiny exported pack; also with spaces and brackets in the folder name, and with the relative `extends "src/x.gd"` chain). So the zip can simply be extracted into the game folder. `user://...` paths (settings, tutorial flags, `walkmap.png`) still point to `%APPDATA%\Godot\app_userdata\Buckshot Roulette\`. NOT yet confirmed in the real game (custom Windows build).
- **Launcher** (`release/launcher/*.go`, Go, no dependencies, GUI subsystem = no console window, built for Windows amd64): checks `Buckshot Roulette.exe` and `vr_mod\vr_boot.gd` are next to it, creates `override.cfg` if missing (refuses and explains if another `override.cfg` does not load the mod), starts the game with `--xr-mode on` in the game folder; extra arguments are passed through; `--flat` = no `--xr-mode`. Logic tested on Linux with a fake game script (plain start, extra args, `--flat`, foreign override, missing mod, missing game, other working folder). `msgbox_windows.go` shows errors in a message box; `msgbox_other.go` prints them (for tests).
- **Release zip** (`tools/make_release.py --version X`): runs `check_modules.py`, builds the exe (Go; or `--exe`), zips `Buckshot Roulette VR.exe`, `override.cfg`, `READ-ME.txt`, `vr_mod/vr_boot.gd`, `vr_mod/src/*.gd`, `vr_mod/LICENSE`, `vr_mod/VERSION` with fixed timestamps, writes `dist/SHA256SUMS.txt`. Never includes `hands/`, `archive/`, `tests/`, `tools/`.
- **GitHub Actions** (written here, never run yet): `release.yml` (push a tag `vX.Y.Z` -> build -> `gh release create ... --prerelease` for `v0.*`; notes from `release/RELEASE_NOTES.md`), `tests.yml` (downloads Godot 4.1.1 and runs `tests/run.sh`, about 15 minutes).
- Caveats: unsigned exe (SmartScreen / antivirus may complain); a game update can break the mod; only Quest 3 + Virtual Desktop tested.

- `_fx_*`: tiny effects list `fx_list` updated by `_fx_update(delta)` (falling clones with spin and a floor, `CPUParticles3D` shards); `_anim_stream(animation, word)` takes an audio stream out of the game's own animation tracks (guarded with `has_animation`); `_fx_play` plays it. Nothing is copied from the game into the mod's files.
**Cuffed hands** (`_update_cuffs(delta)`, after `_update_items`; rebuilt in iteration 23): `cuffed` = `RoundManager.playerCuffed` with both hands tracked. The game's own handcuffs are the node `handcuffs player bar` (a `MeshInstance3D` under `player cuff bar` in the main scene; `HandcuffManager.AttachHandCuffs` plays `RESET` and shows it after 0.1 s; its `AnimationPlayer` is `animator_handcuffs player bar` next to it; the game plays `check handcuffs` (a tug) and `player break handcuffs` on it). Its two animation poses: position/rotation `CUFF_POS_A` / `CUFF_ROT_A` (rest) and `CUFF_POS_B` / `CUFF_ROT_B` (the tug; only the position and yaw differ).
While cuffed and the bar is visible: both hands show the fist (`holding`, remembered in `cuff_fist`); each wrist (7.5 cm ahead of the grip) is taken as an offset from where it was when the cuffs went on (`cuff_anch`, rig space); the mean offset along the pull axis (B - A in world) over `CUFF_FREE_M` 0.06 m gives `cuff_t` (0..1, smoothed), and the bar's `position` / `rotation` are `lerp(A, B, cuff_t)` - unless the game's own animation (not `RESET`) is playing, then the bar is left alone. The bracelets are `CUFF_RING_L` / `CUFF_RING_R` in the bar's own frame (**estimated** from the model, not verified); which hand gets which is decided once when the cuffs go on (screen side, `cuff_swap`). Each hand visual is moved so that its wrist is at its bracelet plus its offset (minus how far the bracelet moved), clamped to `CUFF_FREE_M`; blended in over `CUFF_BLEND_S` (`cuff_blend`); beyond the clamp both controllers buzz (`cuff_buzz2`). An item in hand is put back when the cuffs go on; no gun / item grab while cuffed; a gun that is only picked up is put back. When the cuffs come off the fists open. Our own rings and chain (`cuff_nodes`, `_cuffs_build`) are gone.
**Permissions**: `interactionAllowed` of the branch (`_allowed`) is the turn lock. `_perm_back()` calls the game's `itemInteraction.EnablePermissions()` after a ritual (as the game does at the end of an item's animation).

### Nudge mode for the gun hand (iteration 22)
Why: the hand pose is the game's own gun grip, but where the gun sits relative to the real hand could not be verified offline. `gun_cal` (Vector3, real metres in the grip frame of the right hand; x mirrored for the left; clamped to +-`GUN_CAL_MAX` 0.08; setting keys `gun_cal_x/y/z`) is added to `GUN_HAND_HOLE` in `_gun_pose`. The stick click of the hand that holds the gun (`gun_state == 1`, handled in the stick-click code instead of recenter / panel) calls `_gun_cal_toggle`; while `gun_cal_on` (`_gun_cal_tick` in the state-1 branch of `_update_gun`): gun-hand stick x / y = side / up, other hand's stick y = in / out (`GUN_CAL_RATE` 0.03 m/s at full deflection, dead zone 0.2), B / Y of the other hand = reset to zero, a hint sign explains it. Walking, snap turning, menu arrows and `ui_cancel` are suppressed (`gun_cal_on` checks in `_walk_input` and the button code), `_gun_aim_update` is not called (no aim lock, no shot). `_gun_cal_end` (second click, the game taking over the gun, `_gun_release`) saves the settings.

### Doors open with the trigger (iteration 21)
`DOOR_ALIASES` = `bathroom door`, `backroom door` (they stay in `POKE_ALIASES` as fingertip-touch targets). In `_update_poke` each hand has `trig_now = hh.trigger_down` and `trig_edge = trig_now and not door_trig[hand]` (the previous-frame value; `hh.trigger_down` is refreshed in `_update_buttons` later in the frame, so the edge is one frame late, which does not matter). A door alias fires (`_poke_fire`, cooldown) only when the tip touches it, the edge is fresh and the hand does not hold something (`not hh.holding`).
A trigger already held on arrival, or pulled away from the door, does nothing. Iteration 21 had a small sign (`hint_label`) here; since iteration 23 there is no text: the lime frame of the door (`poke_boxes`) is the only indicator. `hint_label` / `_hint_show` / `_hint_finish` remain for the nudge sign.

### TV and back-room door by fingertip (iteration 16)
`POKE_ALIASES` = crt, crt button, bathroom door, backroom door. The TV screen (`crt`) is not a target any more but still sets `restroom_stage` (hides the laser, blocks world clicks); while `tv_state == 0`

### Hands
Procedural finger-curl poses on the game's dealer-hand mesh. Two shaders: `HAND_LIT_SHADER` (default, `hand_lit`): normal lit
material so the game's lights colour/dim the hands, plus 12% self-light so they never go black; `HAND_SHADER`: old flat unshaded look

## How to test without a headset
Offline suites live in `tests/` (see `tests/README.md`): `tests/run.sh /path/to/Godot_v4.1.1-stable_linux.x86_64 [suite ...]` runs the real mod code headless against mock game objects (`tests/mocks/`) and compares the result lines with `tests/expected/<suite>.txt`. Eleven suites: `two_hand_stolen_items` (iteration 37), `inverter_cigarette_frames_sign` (37), `self_aim_mouth` (38), `inverter_dealer_hand_frames` (35), `iteration35_regressions` (35), and the regression suites of iterations 29-33 (`regression_*`). Run one after the other (they share one settings file). A suite is `head` (builds the mock scene) + a body of checks that print `X1 ... (want ...)` lines; copy the closest suite to add a test.
- Cloud sandbox (no Vulkan): download Godot 4.1.1 Linux once per session
  (`https://github.com/godotengine/godot/releases/download/4.1.1-stable/Godot_v4.1.1-stable_linux.x86_64.zip`, unzip to `/tmp/godot_dl/`).
- Parse check: load the entry script from a tiny test script and print `can_instantiate()` (a parse error prints only the banner); `--check-only` prints nothing useful for this autoload.
- Shader compile + look: `xvfb-run -a godot --rendering-driver opengl3 --path <tmpproject> -s shot.gd`, extract the shader text from the `const NAME := """ ... """` blocks (`grep -n '"""' src/*.gd`), put it on quads/spheres, save `root.get_texture().get_image()`. Only the ALSA audio error is normal. Compat compile success is a good (not perfect) proxy for the Vulkan renderer. (This render harness is not in the repo.)
- Not testable offline: how things look and feel, real tracking, the Vulkan renderer, the game's own scripts (only mocks of them).
- Patch method: copy the tree to a work folder, apply a Python script of exact-match `replace`s (assert count == 1; tabs, not spaces), run `check_modules.py` and the suites.

## Gotchas and lessons

- Always check what a shader/engine feature needs against 4.1.1; do not trust 4.2+ docs.
- Do not `walk_off = ZERO` or call `_place_origin` while the anchor and the player are in different places; use `_sync_walk_off()`.
- A scripted camera jump must not look like a cut: set `prev_cam_pos` after a `seek`, and ignore cuts while `kick_on`.
- The click path: `_update_buttons` -> `_note_click_target()` -> `_world_button(true)` (synthetic mouse click far outside any 2D control;
  the game's InteractionManager sees it in `_input`). `play()` of the game animation happens inside that call, so `_update_door` sees
  it on the next frame.
- The game's leg and highlight frames are clutter at the table; hide them with `layers = 0`, never `visible` (the animation toggles `visible`).
- Never feed a measurement that depends on `world_scale` back into the scale (use raw poses); the XR server rescales node positions with the new scale.
- Do not re-run `find_child` every frame (throttle it); the main scene is huge.
- Memory/prompt hygiene: never copy the game's assets into deliverables.
- Godot's front faces are clockwise: the outward normal of a triangle (a, b, c) is `(c - a).cross(b - a)`; with `(b - a).cross(c - a)` you get the inside (a table's underside).
- A ritual that returns early before it updates a reference (`rit_prev`) must keep updating it, otherwise the first real frame sees one huge step.
- GDScript lambdas capture locals by value and cannot change outer variables; keep test state in an Array / Dictionary or on the node. `as AABB` is not valid on a Variant (use a typed local or `is AABB`). Headless `Mesh.surface_get_arrays` is empty (no rendering server), so code that reads mesh triangles needs a fallback (`_mag_raster_fallback`) and the tests cover that path. `get_process_delta_time()` is 0 headless.
- `poke_boxes` entries are AABB or Dictionary ({"flat"} / {"face"}); every consumer must handle both.
- The shotgun's grab can take a free hand near the gun's axis before the item logic runs (seen as an edge case for the inverter dial lying on the gun's axis); not fixed.
- A smash test of the magnifier is a speed test: a test that teleports the glass near the table counts as a fast stroke.
- While the game lets you steal, `items_dynamic*Array` also holds the player's own items: every pick-up filter during stealing must check `isDealerItem` on the item's `PickupIndicator` (child 0).
- A test hand left standing near an item takes part in the next pick-up (adrenaline test R7): move the other hand away before creating the next test item.
- Properties the game may lack (mocks, other versions) must be read with `== true`, never `bool(x)` (a null crashes the constructor); a numeric field that may be missing (`amount_dealer`) is checked for null before `int()`.
- A test mock click box (40 units) is not the real gun frame: the in-box rule must not apply while a hand works on an item, or every item near the gun loses its squeeze.
- `queue_free` does not run between headless test steps: check `is_queued_for_deletion()` when asserting that a node is gone.
